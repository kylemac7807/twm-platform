# Kyle's feedback on the review workbench prototype (October 13, 2026)

Consolidated by Kyle in a separate chat and pasted into the main session as given. The answers to the open questions and the plan for the NOW items are in `plan-v3.md`.

Below is my feedback, split into NOW (build in the next iteration) and LATER (don't build yet, but don't design anything that blocks it). After that is a list of open questions.

Before changing any code:
1. Answer the open questions in plain language.
2. Give me a short plan for the NOW items, flagging anything that conflicts with how the system works today.
Wait for my go-ahead before building.

## NOW

**Home: start by choosing a contract set**
1. The landing page should start with choosing the contract set to review. Everything else follows from that choice.
2. Show the full list of contract sets, each with a status: Not processed (hasn't been through the first engine steps); Ready for review (show the number of questions); In review (e.g. "12 of 40 answered"); Complete. With hundreds of contract sets, I need to find unfinished work without opening each one.
3. Move the summary numbers (rates found, in benchmarks, held back, decided by you) off the global landing page. Show them per contract set, once one is selected. Global running totals won't mean anything after hundreds of sets.
4. "Up next" should be scoped to the selected contract set, not a global queue.
5. Remove the "Hello" label at the top.

**Contract set names**
6. Give each contract set a readable name instead of the file name (e.g. not "081_Texas_..."). The system proposes a name; the analyst confirms or edits it. Prefer building the name from fields the engine already extracts (vendor, client, contract type, date) so the workbench still makes no AI-model calls. If that isn't enough, tell me before adding a model call. Keep the file name visible as a secondary line under the assigned name.

**To review: task card**
7. Every answer (job titles, place names) gets a scope: local (this contract set only) or global (all contract sets). Default to local; global must be a deliberate choice. See open question B on a possible third level.
8. Step 2: the system should propose a role, pre-selected, so the analyst confirms or changes it rather than picking from 129 roles.
9. Step 2: the "Technology" label is confusing. Reword it or add a short explanation with an example. See open question C.
10. "Why the system is asking" (folded section): make it readable and usable. Lead with one plain sentence; keep the technical reason folded beneath as the audit trail.
11. "Can't decide yet" vs "Skip": I can't tell them apart, so a CIO won't either. See open question D. My leaning: merge them into one "Park" button with an optional note, and a parked list I can return to.

**Apply decisions**
12. The purpose of this screen isn't obvious. It needs a plain one-line explanation at the top, and possibly a clearer name. See open question A.

## LATER

13. Login. Identify each user by their account instead of a typed name, and log all activity per user, not just saved decisions. Decisions already saved under a typed name should carry over and link to that person's account so the audit trail doesn't break.

## OPEN QUESTIONS

A. What does Apply decisions actually do, and why is it a separate manual step from saving an answer? Explain it as you would to the analyst. Also: with local/global scope, should only global answers go to this screen (since only they become permanent role-framework rules)?

B. Should scope have two levels (this contract set, everyone) or three (this contract set, this client, everyone)? Place names are already answered per client today. Recommend one and explain the trade-off.

C. Confirm what the "Technology" field is for. My understanding: for "Senior Java Developer," role = Developer, band = Senior, technology = Java, which keeps the framework clean while recording the skill. Is that right? Suggest clearer wording (e.g. "Technology named in title (optional)").

D. What is the actual difference between "Can't decide yet" and "Skip" today: what gets recorded, and where does the item go? Then recommend whether to merge them.

E. Once Home starts with choosing a contract set, Home and Documents both start from the same list. Should they become one place, with the selected contract set showing its review queue and its documents side by side? Recommend yes or no.

F. Does the "Hello" label appear only on Home or on every screen?
