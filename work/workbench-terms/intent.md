# Intent: terms in the workbench

**Kyle said go on November 22, 2026** (action items B32 and B33). Built in the main session, on the workbench as it stands after his October feedback.

## The problem

The engine now reads a contract's words: the facts (parties, contract number, value, dates, the amendment chain) and the conditions (the fine print that changes what a printed rate really costs, or whether it can be compared). The Texas and Michigan contract sets alone hold 120 facts and 213 conditions, each proven on its page. None of it can be seen. It sits in a database in another folder, and three kinds of question are waiting with nowhere to be answered: 41 conditions the inventory has no name for, printed vendor names nobody has confirmed, and one contract set whose disclosure check came back "restricted".

The workbench also still shows the October picture: 53 Texas rates, not the 1,648 across every contract year.

## What we want

1. The main ledger brought up to date: both contract sets re-run into it from the model's cached answers (no spend), older questions from the superseded run closed so nothing is asked twice.
2. A **Terms** tab on each contract set: the disclosure check first, then the facts, then the conditions grouped the seven ways the inventory groups them. Click a condition and see the clause on its page, boxed, the way a rate is traced today.
3. Three new kinds of question in **Review**, each a task card like the job-title one: name this condition (pick an inventory row, or propose a new one); which vendor is this printed name; clear this disclosure flag. Every answer carries the same scope as a job-title answer: this contract set, this vendor, everyone.
4. The confidence floor for terms (0.75) as a setting applied when the screen reads the data, so moving it re-sorts recorded and flagged at once, and no row is rewritten.

## Rules that bind this task

A condition never changes a stored rate. Nothing is guessed: an unnamed condition stays flagged until a person names it. The workbench still never writes to the inventory or the framework files; a proposed new condition is a nomination on Global Framework Updates. Plain words on every screen: "conditions", not "terms typed by key"; the clause quoted as printed.
